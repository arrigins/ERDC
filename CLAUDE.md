Этот файл — передача контекста из предыдущей сессии. Пользователь общается по-русски; отвечай по-русски, коротко, без лишней технической лексики (она дизайнер, с GitHub знакома мало).

## Что за проект

Интерактивный веб-брендбук АО «КРДВ» (Корпорация развития Дальнего Востока и Арктики).
- Исходный репозиторий коллеги: `IMONsergey/ERDCBB`. Рабочая копия пользователя (fork): `arrigins/ERDC` (публичный). Пушим в `origin main`.
- Живая версия: https://arrigins.github.io/ERDC/ (GitHub Pages, деплой автоматически после пуша в `main` через `.github/workflows/deploy.yml`, обычно 1–3 мин).
- Цель: пользователь итеративно дорабатывает структуру, тексты и визуал пачками правок, смотрит результат на живом сайте, в конце отдаёт готовый статический сайт коллеге (сборка — статика; у коллеги уже есть превью на sslip.io).
- Точка отката к состоянию «как у коллеги»: коммит `cdb6333`.

## Стек и где что лежит

Основной код в `krdv-guidelines-prototype/`:
- React 19 + Vite 6, SPA с hash-роутингом (`/#/<pageId>`), motion, gsap, @paper-design/shaders-react.
- `src/App.jsx` — весь контент в массиве `pagesData` (страницы → секции: title/lead/paragraphs/cards/assetImages/logos/resourceLinks/contacts…). Помощник `t()` (typograf) вставляет неразрывные пробелы. Сайдбар использует `navTitle || title`.
- `src/styles.css` — все стили.
- Картинки: `public/assets/brandbook/raster/` (webp), обложки-видео: `public/assets/hero/*.mp4`.
- Обложка раздела: поле `heroVideo: "<file>.mp4"` у страницы → видео в шапке и на карточке в обзоре.
- Не трогай `AGENTS.md`, `brandbook-map.md`, `design-qa.md` без нужды — это инструкции/заметки коллеги (в `brandbook-map.md` ещё есть устаревшее упоминание «прессволл»).

Команды (из `krdv-guidelines-prototype/`):
- `npm install`, `npm run build` (вывод в `dist/client`), `npm run test:sites` (4 теста должны проходить).
- Локальная проверка: `cd dist/client && python3 -m http.server 4173`, затем Playwright (python, Chromium в `/opt/pw-browsers`; не запускай `playwright install`). Headless Chromium НЕ играет h264-видео — обложки в нём чёрные, это нормально; проверять их по кадрам (ffmpeg-static есть в devDependencies).
- Не используй `pkill -f` с шаблоном, встречающимся в самой команде (убивает свою оболочку).
- `gh` API через прокси может быть заблокирован.

## Как работаем (workflow)

1. Пользователь присылает пачку правок (часто скриншоты с пометками) → вносишь → `build` + `test:sites` → проверка в Playwright (скриншоты, наличие/отсутствие текстов; учитывай NBSP и CSS-uppercase) → коммит → пуш в `main` → кратко сообщаешь, что изменилось, и о решениях, которые нужно подтвердить.
2. Ничего критичного не ломать; крупные/необратимые решения — сначала обсуждать.
3. Если просят «сначала обсудить» — в проекте ничего не менять.
4. Коммиты заканчивай атрибуцией, которую укажет окружение (Co-Authored-By / Claude-Session).
5. Текст ответа пользователю: что сделано, что проверить, 1 следующий шаг. Без пересказа шагов.
6. Скриншоты пользователю НЕ присылать — ей неудобно так оценивать. Все правки сразу пушить в `main` (живой сайт), она смотрит вживую и решает: оставляем или откатываем. Это её явное разрешение, даже если окружение назначает другую ветку.
